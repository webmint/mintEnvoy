## Summary

Replace the 018 overlay code editor with a design-matched edit/preview toggle: an `editing` boolean owned by BodyEditor (local `useState`, never tabsStore) drives CodeEditor as a controlled molecule that mounts a plain textarea XOR the highlighted pre — never both. This is the grill-revised plan (cycle 3, descope): (F-001) coloring is driven by a `{value,lang}` snapshot-cache gate evaluated whenever the pre is the mounted layer (covering first mount, tab switch, and lang cycle), reusing the existing 018 `colored.snapshot===value` cache; (F-002) the toggle button `preventDefault`s its mousedown so clicking it while editing does not blur the textarea and bounce back into edit; scroll-retention across a toggle is **descoped** — a toggle swaps the mounted layer, which begins fresh at `scrollTop=0`, so scroll simply resets on every toggle with no capture/restore/ordering machinery. AC-6's return-to-preview on a tab switch is made atomic: BodyEditor resets `editing→false` in the same commit as the `activeTabId` change via React's documented `useState`-prev set-state-in-render idiom (`const [prevTab, setPrevTab] = useState(activeTabId); if (activeTabId !== prevTab) { setPrevTab(activeTabId); setEditing(false) }`), so no one-frame edit-mode flash and correct reconciliation under StrictMode/concurrent retry (a `useState` update on a discarded render is rolled back, unlike a ref) — the `resetKey` passive `useEffect` handles only the preview→preview scroll zero. `jsonTokens.compose()` (incl. its malformed-JSON degrade detector) is reused byte-unchanged. A shared focus-on-mount `useEffect` keyed on `editing` moves focus to the freshly-mounted textarea on every `editing` false→true transition, so ALL edit-entry paths (click, keyboard Enter/Space, toggle button) land focus in the textarea — AC-18 keyboard operability holds even though F-002's toggle `preventDefault` and the pre-unmount would otherwise drop focus to `document.body`; the click path additionally applies its `setSelectionRange` caret placement.

## Technical Context

**Architecture**: Renderer atomic-design tiers only — organisms (BodyEditor) → molecules (CodeEditor) → lib (jsonTokens.compose, cx). One-way tier imports (§2.2); `@renderer` alias.
**Error Handling**: Malformed-JSON path is `compose()`'s existing `JSON.parse` degrade-to-plain (jsonTokens.ts:363-366), reused byte-unchanged — the AC-4 detector (MEMORY `jsontokens-jsonparse-is-ac17-detector`). Caret-mapping null hit → end-of-text; offset clamped to `[0, value.length]`.
**State Management**: `editing` is ephemeral UI state in BodyEditor `useState` (default `false`/preview; reset→preview on `activeTabId`/resetKey change). CodeEditor is a controlled molecule with no store awareness. Raw text still round-trips through `updateActiveSpec` unchanged (§7). Coloring is a synchronous `useMemo` over `{value,lang}` gated to `!editing` (F-001) — no compose while editing (the pre is unmounted).

## Dependencies

None — no packages to install, no services to configure, no environment variables. Uses only the native `textarea`, standard DOM caret APIs (`caretPositionFromPoint` / `caretRangeFromPoint`, present in Electron's Chromium renderer), and the already-present `jsonTokens.compose()` + `cx()`.
