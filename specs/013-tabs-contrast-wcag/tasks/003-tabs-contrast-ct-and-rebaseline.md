## Description

Add Playwright CT assertions that pin the Tabs strip's fixed text colors, then regenerate the three committed screenshot baselines the token darkening shifts app-wide (spec Risk R1).

**Assertion semantics (architect ruling):** these are computed-color EQUALITY assertions in the existing `Tabs.ct.tsx` idiom — `getComputedStyle(el).color` (or `.backgroundColor` for the dirty dot) equals the resolved token rgb — NOT a WCAG contrast-ratio calculation (Playwright CT has no native ratio helper, and the resolved-value equality is the authoritative proof the correct token/value is bound). Assert BOTH themes: default (light) and with `document.documentElement.dataset.theme = 'dark'` set before the measurement (no existing CT sets dark theme — this is a new harness technique; mirror the existing `beforeEach` `data-mstyle` mount pattern, resetting the attribute so tests stay isolated).

Use the existing `.tabbar`-scoped fixtures (e.g. `TabbarFidelityFixture`) for the active-tab and close/dirty sites so the rules render in their real scope, per the file's grill-binding F1 note.

**Token → rgb map (for the expected values):**
- `--text`: light `#18181b`→`rgb(24, 24, 27)`; dark `#f4f4f5`→`rgb(244, 244, 245)`
- `--text-muted`: light `#6c6c75`→`rgb(108, 108, 117)`; dark `#a1a1aa`→`rgb(161, 161, 170)`
- `--text-faint`: light `#6e6e77`→`rgb(110, 110, 119)`; dark `#787881`→`rgb(120, 120, 129)`

**Re-baseline:** all three baselines are regenerated by running the CT suite with `--update-snapshots` (`npm run test:ct -- --update-snapshots`). Inspect the regenerated PNGs to confirm the shift is the intended text darkening (not an unrelated regression) before committing them.
