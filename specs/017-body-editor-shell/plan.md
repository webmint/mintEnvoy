## Summary

Add the `BodyEditor` organism to the Body sub-tab: a 6-option ARIA radiogroup drives a mount-all/hidden-toggle mode switch across three live modes (none, raw, x-www-form-urlencoded) plus three payload-free placeholder discriminants (form-data, binary, GraphQL). `RequestSpec.body` migrates from a flat `{lang,type,text}` descriptor to a **store-owned tagged record `{active, raw, urlencoded}`** whose always-present per-mode sub-records give AC-14 round-trip with the tabsStore as the single source of truth (the grill F-001 fix — a single-slot union could not retain more than one mode's value). A new renderer-pure JSON tokenizer lib powers a hand-rolled textarea-over-`<pre>`+gutter code area with two-pass `{{var}}`+JSON highlighting. §8 design fidelity is verified by new fail-closed CT computed-style helpers.

**Why no new research**: The A/B/C design alternatives and the build-vs-buy verdict were settled in the upstream `/discover` handoff — this plan seeds from its plan-seeds rather than rediscovering, and no new external dependency is introduced (every seam is internal and already present). Consulted findings quoted from `discover/2026-07-10-request-body-editor-shell-with-a-body-type-selector-plus.md`: (1) "the migration is consumer-free (zero readers of .body.text/lang/type beyond makeBlankRequest), so it is Low-risk"; (2) "Monaco/CodeMirror render their own DOM and theming, which defeats the design-anchor computed-style diff against reference.html"; (3) "the canonical react-simple-code-editor technique — transparent textarea, CSS-Grid alignment, single scroll source". No `research.md` generated (skip-with-reference to the discover doc, cited in Supporting Documents).

## Technical Context

**Architecture**: Renderer atomic-design — new organism (`BodyEditor`), two new/changed lib modules (`requestSpec` Body model, new `jsonTokens`), one modified organism (`KVTable` controlled mode), one modified host organism (`RequestSubTabs` body slot), composition wiring in `App.tsx`, styling in `tokens.css` + new `BodyEditor.css`, CT utils. Dependency direction stays downward (organisms → lib; lib imports nothing renderer-external).
**Error Handling**: Renderer-pure graceful degradation — tokenizer never throws (empty → zero tokens; malformed JSON → single plain `var(--text)` segment); CT fidelity helpers fail-closed to UNVERIFIED, never a hard error.
**State Management**: Body lives solely in `tab.spec.body` (tabsStore SSOT) as a tagged record `{active, raw, urlencoded}`; the `raw` and `urlencoded` sub-records are ALWAYS present, so every value-bearing mode's VALUE round-trips through the store (AC-14). `BodyEditor` reads via a tabsStore selector and writes an immutable full-`Body` patch via `updateActiveSpec({ body })` (mode switch mutates only `active`, carrying both sub-records forward). mount-all + `hidden`-toggle preserves only DOM-local state (scroll/caret) and satisfies AC-6 — NOT values; values live in the store. **Re-select dirty guard (general rule)**: every control that writes a fresh `body` early-returns when its next value equals the current stored value — the radio (`next === body.active`) AND the lang-pill (`next === body.raw.lang`) — because the store no-op guard is reference-based (tabsStore.ts:344) and cannot catch a fresh-but-equal object; urlencoded-rows and raw-text edits are genuine changes, no guard (F2). **Highlight scheduling (F3)**: the raw `<textarea>` stays store-controlled (`value = body.raw.text`, per-keystroke write → AC-14 + single SSOT). The aria-hidden `<pre>` overlay and the gutter render their TEXT from the LIVE `body.raw.text` every keystroke (plain-text render is O(n)-cheap, no tokenise) — so typed chars are visible immediately (the `<pre>` is the sole visible text layer under the `color:transparent` textarea) and the gutter stays aligned. ONLY the expensive `compose()` coloring pass is debounced (`BODY_HIGHLIGHT_DEBOUNCE_MS`, default 100ms): its token spans apply to the `<pre>` only when the debounced snapshot === the live text (typing paused); while a burst is in flight the `<pre>` renders the live text as plain `var(--text)` segments (D6's plain-degrade path). So `compose()` runs off-keystroke (spec §7 c3b) WITHOUT the visible text ever lagging (F3 cycle-3).

## Constitution Compliance

- **§2.2** (no sibling-organism import): AT RISK — mitigated. `BodyEditor` must NOT import `KVTable`; the urlencoded editor is injected as a **render-prop slot** (`renderUrlencoded`) wired at the App composition root (App is the sanctioned cross-organism composer). Review must assert `BodyEditor` imports zero sibling organisms. Unchanged by the revision.
- **§5.2** (requestSpec component-invisible): compliant for new code — the `Body` + sub-record types (`RawBody`, `UrlencodedBody`, `BodyType`, `RawLang`) and `Row` reach `BodyEditor` via a `tabsStore` re-export (AC-13); requestSpec stays imported only by tabsStore. Pre-existing type-only `import type { Row }` from `requestSpec` in `KVTable` (L8) is a documented deviation left UNCHANGED (grill U-003 Info/dismissed; out of scope; "never fix unrelated code") even though KVTable's props change.
- **§3.1** (strict, no any, narrow-don't-cast): compliant — and improved. The tagged record needs NO narrowing to reach `body.raw`/`body.urlencoded` (always present); `KVTable` narrows via `'rows' in props`; no casts. `isRawBody` is REMOVED (no union left to narrow — it would be dead code). The KVTable prop union intersects the shared optional `validVars?` onto both arms (`(… | …) & { validVars? }`, F4) — `validVars?` is present-optional, NOT a discriminant, so `'rows' in props` narrows cleanly on both arms and the existing `.missing`-highlight CTs keep type-checking. **Exclusivity is enforced at RUNTIME by `'rows' in props` narrowing (every call site passes exactly one shape), NOT by the type system** (F-002 cycle-3): the bare object-type union WITHOUT `?:never` companions makes neither-props a type error but does NOT reject both-props (`{field, rows, onRowsChange}`) — excess-property checking admits it since each property exists on some arm. The `?:never` form was rejected (see D3) as non-minimal for a non-functional Info finding; the plan does not claim type-level XOR.
- **§2.1/§2.3** (renderer purity, @renderer alias, no inline styles): compliant — `BodyEditor` + `jsonTokens` are browser-only, class-based (AC-29), alias imports; new lib imports nothing renderer-external.
- **§4** (tokens over literals): AT RISK — mitigated. Design pins literal per-theme hex for 4 syntax colors. Introduce `--tk-key/str/num/bool` per-theme tokens set to those literals; `.tk-*` classes bind via `var()`, so computed style resolves to the literal hex — satisfying both §4 and the literal-hex fidelity assertion (the documented fidelity-driven token exception). Unchanged by the revision.
- **Round-trip invariant** (`RequestSpec` survives `JSON.parse(JSON.stringify(...))` deep-equal): HOLDS — every `Body` field is a JSON primitive/array/plain-object.

### Established-Convention Departures

| Departure | Established Pattern Left | Why Necessary |
|-----------|--------------------------|---------------|
| Body modeled as a tagged record with always-present retained sub-records (`{active, raw, urlencoded}`), not a discriminated union + guard | The module's `Auth = NoneAuth \| BearerAuth` discriminated union + `isBearerAuth` guard (same file) | A single-variant union holds exactly one mode's payload; switching `active` via `updateActiveSpec({body})` would erase the prior mode's value, making AC-14 ("restore each mode's prior value") structurally unsatisfiable (grill F-001, confirmed). Retained sub-records keep every mode's value in the store simultaneously with a single SSOT (no dual-source draft, §5.2) |
| Body deferred trio (form-data/binary/GraphQL) modeled payload-free `active` values, not `Row[]`-carrying | Spec §3 narrative implies `Row[]` on form-data/urlencoded | No in-scope AC writes/persists the deferred trio's rows and §6 marks their impl OOS; carrying `Row[]` now is inert dead state (KISS). form-data's future `Row[]` is that deferred feature's own migration |
| KVTable urlencoded injected via a **render-prop** slot | RequestSubTabs slot props are static `ReactNode` | The injected child is parameterized by BodyEditor-owned `body.urlencoded.rows` + write callback; a static node cannot carry that binding without App subscribing to body state per keystroke. Render-prop keeps KVTable's import in App only (§2.2) and the body write in BodyEditor only |
